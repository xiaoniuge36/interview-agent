# 练习解析页回答阅读体验设计

## 目标

将“解析与 AI 评价”里的原回答从一段无层级的长文本，改成可快速扫读、可定位论点、可按需展开的复盘阅读内容；不改变回答、解析或 AI 评价的后端数据。

## 用户与页面职责

用户是刚完成一道练习题的求职者。页面只做一件事：先让用户看懂自己的回答结构，再比对标准解析和 AI 反馈，最后决定返回修改还是继续下一题。

## 布局与视觉

保留既有深色步骤头与 AI 评价卡。原“我的回答”卡升级为回答阅读台：顶部说明保存状态、字数、标签和可阅读段落数量；内容区把 Markdown 风格的标题、段落、引用、清单与代码块渲染成不同的阅读块。标题拥有细蓝色轨道，引用使用浅青提示面，代码使用深色等宽面，普通段落保持宽松行距而不再保留原始 `#`、`>`、围栏标记。

默认展示前四个阅读块；超过四块时显示“展开剩余 N 段”，展开后可收起。没有可识别 Markdown 的回答仍会作为段落正常显示。手机端保持一列、全宽按钮和不小于 44px 的触控目标。

## 数据与边界

- 只在前端把 `draft` 文本拆为展示块，不调用模型、不改接口、不推断 AI 对每个段落的评价。
- 解析规则只覆盖标题、引用、无序或有序清单、三反引号代码块与普通段落；未知格式原样作为段落保留。
- 本次只在教练页接入纯解析模型；模型保持独立，后续复盘弹窗需要结构化呈现时可直接复用。

## 验证

- 单元测试覆盖五类块、收起状态与空回答。
- 教练页渲染测试确认出现结构化阅读、展开控件和既有 AI 评价入口。
- 运行用户端定向 Vitest、TypeScript 与生产构建，并用截图检查桌面与移动布局。
