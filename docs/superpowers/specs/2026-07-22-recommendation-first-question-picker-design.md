# 推荐计划优先的题库设计

## 目标

将题库页从“先筛选题目再组卷”调整为“先开始 Agent 推荐训练；需要时再自主组卷”。用户打开页面后应能立即理解今天的推荐、推荐依据和开始动作，同时保有完整、可控的自选能力。

页面面向正在准备 AI/Agent 岗位的求职者；单一任务是以最少决策成本开启一轮有针对性的训练。

## 范围与约束

- 只修改用户端题库页面、推荐展示、自选入口和相关局部样式、静态测试。
- 不修改推荐算法、请求、合同、题单创建、评分、持久化、路由、认证、主题存储或依赖。
- 使用现有主题与强调色变量；不得写死局部颜色或覆盖 dawn、ocean、night、coral、blue、teal、amber 的用户选择。
- 推荐加载、无推荐和请求失败时，明确说明当前状态，并提供“自己组一轮”作为可执行降级路径。
- 自选筛选、跨分页选题、快速组卷和开始练习的既有行为保持不变。

## 视觉方向：推荐计划优先

推荐不是又一张促销卡，而是“今天已经为你排好的训练计划”。它占据首屏主位，使用当前强调色的低对比表面、可解释的训练依据和单一主操作。自选区降为次级工作台：用户仍能筛选、组合和调整题单，但不会与推荐入口争夺注意力。

### 信息结构

```text
今天优先练什么？
推荐题单：标题 · 题目数 · 预计时长 · 推荐依据
[开始推荐题单] [查看题目]

自己组一轮
筛选条件 → 题目列表 → 已选题单 → 开始本轮练习
```

### 签名元素：训练意图卡

“训练意图卡”只使用已有推荐数据：推荐原因、题目数量、难度或标签、预计训练时长。它的视觉轨迹与刷题页的训练证据保持一致，但表达的是“为什么现在练这一轮”，不伪造掌握度或成长数据。

## 页面状态

| 状态       | 主区内容                             | 可执行动作               |
| ---------- | ------------------------------------ | ------------------------ |
| 推荐加载中 | 正在根据已有训练记录准备题单         | 保留自主选题入口         |
| 有推荐     | 题单、理由、题数、预计时长和开始按钮 | 开始推荐题单；展开自选区 |
| 无推荐     | 说明暂未形成个性化建议               | 自己组一轮               |
| 推荐失败   | 说明推荐暂不可用，不影响题库         | 重试推荐；自己组一轮     |

推荐成功时，自选区默认处于收束状态；点击“自己组一轮”后展开筛选、列表和题单。无推荐、加载失败或用户已经选择题目时，自选区保持展开。

## 交互与可访问性

- 推荐主按钮使用已有 `onStart(recommendation)`；不会新增确认、请求或副作用。
- 自选入口使用语义 `<button>` 与 `aria-expanded` / `aria-controls`，展开后焦点保留在入口，键盘用户可继续进入筛选区。
- 推荐依据、加载、失败和自选展开状态都有文字，不依赖颜色作为唯一信息。
- 在小于 `980px` 的屏幕中自选区与题单从双栏变为单栏；在小于 `600px` 的屏幕中推荐操作和自选入口为全宽触达区。
- 只保留已有短过渡，在减少动画偏好下不使用展开位移或卡片入场动画。

## 验收标准

1. 有推荐时，推荐题单及其开始操作在自主筛选之前；自选区默认收束但可完整展开。
2. 无推荐、加载失败或用户开始选题时，自选区清晰可用，不阻塞开始训练。
3. 推荐区和自选区不写死局部颜色，并响应用户主题与强调色选择。
4. 题库相关定向测试、用户端 typecheck、lint 与生产构建通过；不产生 API、合同或数据层改动。
