# 训练证据桌面设计

## 目标

将用户端的“刷题 → AI 复盘 → 训练档案”统一成可连续阅读的训练闭环：用户在每一页都能知道当前训练状态、已经沉淀的证据，以及下一步可执行的动作。

产品面向正在准备 AI/Agent 岗位的求职者；本轮页面的唯一任务是帮助用户完成高质量回答、理解反馈，并基于真实记录开始下一轮训练。

## 范围与约束

- 只修改用户端的刷题工作台、完成复盘、训练档案及其局部样式与静态测试。
- 不修改 API、合同、评分、推荐算法、持久化、路由、认证、主题存储或依赖。
- 沿用现有主题、强调色和字体变量；不得在训练闭环局部重置主题色。移动端保持单栏、触达面积与键盘焦点；尊重 `prefers-reduced-motion`。
- 所有状态文案只陈述已保存、已评价、整轮复盘或已写入的真实状态，不制造即时学习或不具备的数据承诺。

## 视觉方向：训练证据桌面

页面不是普通的仪表盘，而是一张逐步积累的训练记录桌：当前题目是正在采集的证据，AI 反馈是证据解读，整轮复盘与训练档案是可回看的结论。

### Token

| 名称     | 色值                                                             | 用途                       |
| -------- | ---------------------------------------------------------------- | -------------------------- |
| 训练画布 | `var(--surface-subtle)` 与强调色的低透明混合                     | 刷题与档案页面背景         |
| 墨色标题 | `var(--ink)`                                                     | 题目、标题和关键结论       |
| 训练强调 | `var(--primary)`、`var(--primary-strong)`、`var(--primary-soft)` | 当前进度、可执行动作和链接 |
| 掌握状态 | `var(--success)` 与 `var(--success-soft)`                        | 已评价、已写入的正向状态   |
| 提醒状态 | `var(--warning)` 与 `var(--warning-soft)`                        | 待处理或部分可用状态       |
| 内容表面 | `var(--surface)`、`var(--surface-strong)`、`var(--outline)`      | 题目、教练与档案内容表面   |

不引入新字体。标题继续使用现有 UI 字体的紧凑字重与负字距；状态标签使用已有等宽字体变量，形成“训练记录”的语义而不是装饰。现有 dawn、ocean、night 主题和 coral、blue、teal、amber 强调色都必须保持清晰的对比和状态差异。

### 签名元素：证据轨迹

“证据轨迹”是唯一新增的表现手法：一条简洁的连接线或状态带，将“已回答、待评价、整轮复盘、影响下一轮”串成真实的流程。它只展示已有状态，不显示虚构的成长指标。答题页将其置于进度与教练反馈之间；完成页用于说明能力影响；档案页用同一色彩和标签语义展示记录类型与后续动作。

## 页面结构

### 1. 刷题工作台

```text
返回题库 / 本轮名称                回答进度 · AI 评价进度
──────────────────────────────────────────────────────
题目轨道：当前题、已保存、已评价
────────────────────────────┬─────────────────────────
当前题目与答案编辑器         │ Agent 教练
保存与前后题                 │ 解析 / 评价 / 证据轨迹
────────────────────────────┴─────────────────────────
整轮操作：结束自学 / 生成 AI 复盘（含真实影响说明）
```

- 降低背景和装饰的对比，让题目与答案编辑器保持首要视觉权重。
- 题号轨道使用可扫读的状态点，当前题与已完成题有明确差异，不依赖颜色作为唯一信号。
- 教练栏将提示、评价和“Agent 学习轨迹”收束为一个紧凑的证据模块；保留现有操作与加载状态。

### 2. 完成复盘

```text
本轮结论 / 完成方式
本轮证据：回答数 · AI 评价数 · 能力影响
主操作：按推荐开始下一轮
逐题回看：题目、状态、得分或已保存说明
```

- 整轮 AI 复盘突出“已汇总”的结论与下一轮入口；自主结束明确说明回答被保留但不会更新能力画像。
- 逐题回看统一为可点击证据列表，保留当前 dialog 行为。

### 3. 训练档案

```text
训练档案 / 一句话说明                 去刷题 / 开始模拟面试
记录筛选
训练证据卡：类型 · 日期 · 标题 · 事实 · 薄弱项 · 得分 / 状态 · 查看记录
```

- 顶部摘要以“下一轮从薄弱点出发”为核心，而不是营销式大标题。
- 记录卡减少纯边框，使用固定的类型印记、结论区和可扫读信号；分数缺失时始终有等价状态文案。
- 空、加载、部分可用、错误状态使用相同的内容区和下一步动作，避免页面跳变。

## 交互、可访问性与响应式

- 所有可点击卡片和按钮有 `:focus-visible`、悬停与禁用态；信息状态使用文本加图形/布局，不只依赖颜色。
- 互动仅使用已有的短过渡；在减少动画偏好下禁用位移和提示动画。
- 宽屏保持“题目 + 教练”双栏；小于 `900px` 时教练下移，题目轨道可横向滚动；小于 `640px` 时完成复盘和档案记录使用单栏，操作按钮占满可用宽度。

## 验收标准

1. 用户可从刷题页理解本题、整轮复盘和下一轮推荐的关系，且所有文案与实际持久化语义一致。
2. 完成页同时清晰处理 AI 复盘完成和自主结束两种状态，并可逐题回看。
3. 档案页在列表、空、加载、部分可用和错误状态下都有明确的下一步。
4. 现有用户端测试、typecheck、lint 与生产构建通过；不产生 API、合同或持久化层变更。
