# 刷题操作优先级设计

## 目标

面向连续作答的求职者，把“仅保存”和“保存并进入下一题”放进同一操作区，并将后者作为主要动作，缩短完成一题后继续下一题的操作路径。

## 范围与约束

- 仅调整用户端刷题页的题目作答组件及局部样式；不改变保存、切题、题目完成、API 或持久化行为。
- 保留“上一题”和当前题号进度；移除底部重复的“下一题”入口。
- 有未保存内容时，主按钮执行保存后进入下一题；已保存时，主按钮只进入下一题。
- 最后一题不显示进入下一题按钮，保留仅保存及现有完成本轮流程。
- 继续使用 `--primary`、`--primary-soft`、`--surface`、`--outline` 与现有字体变量，兼容 dawn、ocean、night 主题及全部强调色。

## 视觉方向

页面服务于“写完即继续”的单一任务。操作区采用安静的状态提示加右侧双按钮布局：`仅保存`为描边次级动作，`保存并进入下一题`为主题色实心主动作。主按钮采用更大点击面积、明确箭头和克制投影，形成连续作答的视觉终点。

调色仅从现有 token 派生：画布 `var(--surface-subtle)`、表面 `var(--surface)`、边界 `var(--outline)`、主动作 `var(--primary)`、已保存状态 `var(--success)`。不新增字体；题目和输入区继续使用现有 UI 字体与等宽状态文字。

## 交互与响应式

- `保存中`期间两个动作均不可用，避免重复提交或切题。
- 空白回答仍不能执行保存；直接进入下一题继续沿用原有允许跳过题目的行为。
- 通过文字、按钮层级和焦点样式表达状态，不只依赖颜色。
- 宽屏中状态与按钮同一行；窄屏中状态置顶、两个按钮占满可用宽度并保持清晰顺序。遵守现有 reduced-motion 设置。

## 验收标准

1. 作答框下方同时出现仅保存和主连续操作，主按钮文案正确反映“保存并进入下一题”或“进入下一题”。
2. 页脚不再有第二个下一题操作，仍可上一题并显示题号进度。
3. 最后一题不提供下一题按钮，保存行为不变。
4. 定向组件测试、用户端 typecheck、lint 与生产构建可运行并报告结果。
