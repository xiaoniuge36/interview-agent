# 学习中心设计

## 目标

在用户端新增“学习”模块，让用户无需离开产品即可浏览并阅读仓库根目录 `参考资料` 中的 Markdown 文档。新增文档在下一次开发刷新或构建后自动进入目录，不需要同步维护前端数据。

## 范围

- 新增 `/learn` 学习中心入口。
- 自动发现 `参考资料` 下的 `.md` 文件，读取 YAML frontmatter 中的标题、日期和标签。
- 只有一篇文档时直接展示正文；存在多篇时可从资料目录切换。
- 使用 GitHub Flavored Markdown 渲染标题、表格、列表、链接、代码块和引用。
- 桌面侧栏与移动端底部导航均提供“学习”入口。
- 提供文档内章节目录、空目录提示和文档读取失败提示。

## 信息架构

学习中心使用“资料架 + 阅读桌”布局：左侧是自动生成的资料目录和文档元信息，右侧是正文阅读区，正文旁显示当前文档的章节目录。820px 以下资料目录和章节目录移动到正文上方，保持单列阅读。

视觉沿用现有主题 token，并把“资料架”作为本页唯一的标志性元素：文档条目使用书脊式左侧色带表达选中状态，正文区域保持安静、长文友好的排版，不引入新的全局字体或独立品牌色。

## 架构与数据流

1. `learning-documents.ts` 只在服务端访问固定的 `参考资料` 根目录。
2. 文件名经过规范化后形成 URL-safe slug；路由参数只与已发现文档的 slug 匹配，不直接拼接为文件路径。
3. loader 去除 frontmatter，返回序列化后的文档列表、正文和二三级标题目录。
4. `/learn` 默认选择目录中的第一篇文档；`/learn?doc=<slug>` 打开指定文档。
5. React Markdown 在服务端渲染正文，`remark-gfm` 提供表格等 GFM 能力。

## 安全与边界

- 只读取固定目录第一层中的 `.md` 文件，不接受任意路径。
- 不启用原始 HTML 渲染，避免文档内容注入脚本。
- 外部链接增加 `target="_blank"` 和 `rel="noreferrer noopener"`。
- 不保存阅读进度，不接数据库，不抓取参考项目内容。
- Docker 镜像尚未复制仓库根目录的 `参考资料`；本次不修改基础设施文件，容器部署适配作为显式后续项。

## 错误处理

- 目录不存在或没有 Markdown 文档时展示可操作的空状态，并指出资料目录位置。
- URL 中的 slug 不存在时回退到第一篇文档，避免暴露文件系统信息。
- 单篇文件读取失败时跳过该文档；全部失败时进入空状态。

## 测试与验收

- loader 测试覆盖 frontmatter、标题回退、slug、章节提取、排序和非 Markdown 文件过滤。
- 导航测试覆盖 `/learn` 的选中状态。
- 页面组件测试覆盖 Markdown 表格、外部链接安全属性和章节目录。
- 运行 User Portal 定向测试、完整测试、typecheck、lint 和 production build。

## 非目标

- 在线编辑、上传、收藏、阅读进度和全文搜索。
- 将外部 GitHub 仓库内容自动同步到本地。
- 管理后台的学习资料 CRUD。
