# 首页陪练欢迎体验设计

## 目标

让用户进入首页时先获得一句有上下文、低压力的欢迎，而不是直接面对系统化的训练计划。欢迎区应帮助用户确认下一步：继续上一次训练，或从今天的推荐题单开始。

## 范围与约束

- 仅调整用户端首页欢迎层、局部样式和回归测试。
- 欢迎文案只使用认证昵称与现有 `TrainingContinuation`；不请求新接口，不生成画像、进度或训练承诺。
- 保留推荐题单、继续训练、自己组题和所有现有回调行为。
- 使用现有主题 token；移动端保持单列、主操作清晰且触控区域可用。

## 设计方向：陪练开场

首页的第一张深色训练计划卡从“系统推荐结果”改为“陪练已经准备好”的开场。欢迎语是唯一明显的拟人化元素，避免大插画、打卡热力图和凭空生成的成长数据。

| 真实状态       | 主标题           | 辅助文案                 | 行动重心     |
| -------------- | ---------------- | ------------------------ | ------------ |
| 有续练且有昵称 | 欢迎回来，{昵称} | 上次的训练还在这里等你   | 继续现有训练 |
| 有续练但无昵称 | 欢迎回来         | 上次的训练还在这里等你   | 继续现有训练 |
| 无续练且有昵称 | 你好，{昵称}     | 今天，先完成一小步就很好 | 开始推荐题单 |
| 无续练且无昵称 | 你好             | 今天，先完成一小步就很好 | 开始推荐题单 |

右侧展示静态、可访问的“陪练已就位”状态，作为轻量的陪伴感提示；它不代表在线客服或真实人类。

## 组件与数据流

1. `home-welcome-model.ts` 以 `displayName` 和 `TrainingContinuation | null` 生成欢迎标题和辅助文案。
2. `HomeWelcome.tsx` 只负责渲染文案与陪练状态，不持有请求或交互逻辑。
3. `QuestionHubPage.tsx` 从 `useAuth()` 读取 `identity?.displayName`，并把昵称和 `data.continuation` 传给 `AgentRecommendationRail`。
4. `AgentRecommendationRail.tsx` 在现有训练计划头部渲染欢迎组件，推荐与失败状态的行为保持不变。

## 错误、无数据与可访问性

- 身份信息缺失时回退到无昵称的自然问候，不显示技术占位符。
- 续练数据尚未加载或不存在时，按照“无续练”开场处理，不暗示用户曾有训练。
- 欢迎区是说明性内容，不新增可聚焦控件；原有按钮、链接和错误提示保留语义。
- `prefers-reduced-motion` 下不使用依赖动画才能理解的状态。

## 验收标准

1. 首页首屏能显示友好问候，并在有真实续练时表达“可继续”的语境。
2. 昵称缺失、续练缺失时都有自然且不误导的回退文案。
3. 推荐题单、继续训练和自主组题入口均保持可用。
4. 新增模型和欢迎组件具有静态渲染测试；用户端相关测试、类型检查、格式检查、生产构建和 `git diff --check` 有最新验证记录。
