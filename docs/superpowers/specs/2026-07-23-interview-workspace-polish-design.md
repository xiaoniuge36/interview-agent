# 模拟面试工作台体验设计

## 目标

面向正在准备岗位面试的求职者，将“选择岗位 → 接收问题 → 提交回答 → 理解 AI 状态 → 查看复盘”组织成可连续阅读的模拟面试工作台。页面的单一任务是帮助用户在实时追问中保持答题节奏，而不是让用户猜测系统正在做什么。

## 范围与约束

- 仅修改 `apps/user-portal` 的模拟面试呈现、本地派生状态、静态测试与局部样式。
- 不修改 AI 调用、SSE、会话协议、合同、评分、报告生成、持久化或路由行为。
- 进度仅展示真实的已回答次数、当前面试阶段、服务端会话状态与流式处理阶段；不虚构总题数、倒计时、胜率或能力变化。
- 新样式从现有主题 token 派生，并保持 dawn、ocean、night 和四种强调色主题可读。

## 视觉方向：面试席位与会话脉冲

模拟面试不是聊天工具，也不是数据看板，而是一张“面试席位”：当前提问和回答区是桌面中央唯一的焦点，右侧的会话脉冲只说明真实状态、当前考察阶段和已沉淀的复盘。标志性元素是紧贴对话区的会话脉冲——用文字和小型状态条串联“已回答、当前阶段、AI 正在组织追问、报告已生成”，而非装饰性进度环。

基础 token 保持现有主题：墨色 `#24242d`、表面 `#ffffff`、强调 `#df5c3b`、已完成 `#12b981`；在其他主题下全部使用对应 CSS 变量与 `color-mix()` 派生。正文沿用现有 UI 字体；阶段、状态和答题次数使用等宽辅助字体，体现训练过程中的准确定位，而不抢占题目文本的层级。

```text
岗位与本轮焦点 / 开始或重新开始
会话脉冲：已回答 N 题 · 当前考察阶段 · 当前真实状态
────────────────────────────────────────────────
AI 面试官问题 / 流式追问
我的回答编辑器 + 字数 + 提交回答并继续
────────────────────────────────────────────────
右栏：本轮运行状态、可核对依据、已生成复盘
```

## 交互与响应式

- 未开始时清楚说明需要选择岗位并启动；处理中禁用冲突操作，但仍显示当前处理阶段。
- 正在作答时，提交按钮保持唯一主操作，状态消息在按钮附近出现；不改变现有 `required`、长度上限、提交与错误语义。
- 宽屏保持“对话桌面 + 运行状态”双栏；小于 1080px 时状态区下移；小于 760px 时岗位选择、启动操作和答题提交完整可触达。
- 所有状态使用文字、结构和颜色共同表达，保留键盘焦点；在 reduced motion 下取消强化过渡与位移动画。

## 验收标准

1. 用户始终能读出真实的已回答次数、当前面试阶段和会话状态。
2. 岗位选择、启动/重新开始和提交回答的操作层级明确，且不改变现有调用时机或禁用规则。
3. 对话、流式文本、运行事件和报告在桌面与移动端都有稳定层级；空、处理中、完成和错误文案不作虚假承诺。
4. 新增状态派生与界面静态渲染测试覆盖未开始、作答中、AI 处理中和报告完成；用户端 typecheck、lint、测试、生产构建通过。
