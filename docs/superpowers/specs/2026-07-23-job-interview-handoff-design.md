# 目标岗位到模拟面试连续转化设计

## 目标

把 `/job` 从单纯保存表单改造成“确定岗位 → 保存 → 立即开始针对性模拟面试”的连续入口。高频主操作是“保存并开始模拟面试”，低频操作“仅保存”与其同排但保持次级层级。

## 范围与约束

- 仅调整 `apps/user-portal` 的岗位表单、岗位到面试的前端跳转、面试页初始岗位选择和局部样式。
- 不修改 API、合同、数据库、岗位分析、模型调用、鉴权或持久化行为。
- 两个动作共享同一次 `createJobIntent` 请求；只有保存成功后才能跳转。
- 跳转携带明确的 `job` 查询参数；无效或缺失时回退到现有最新岗位。
- 沿用现有主题 token、字体、按钮和通知体系；不增加依赖。

## 体验方向

页面服务于正在准备面试的候选人，单一任务是把一份 JD 变成下一场模拟面试的训练上下文。视觉签名为表单底部的“训练起跑条”：左侧解释保存后 Agent 会如何使用 JD，右侧同排放置“仅保存”和高强调的“保存并开始模拟面试”。

桌面端采用表单与训练重点预览并排布局；预览作为安静的辅助栏，不与主操作争夺注意力。窄屏改为单列，操作按钮占满可用宽度。状态文字通过 `aria-live` 就近反馈，颜色仅作为辅助。

## 行为

1. “仅保存”校验并创建岗位，刷新最新岗位分析，留在当前页。
2. “保存并开始模拟面试”执行同样的校验与单次创建；成功后进入 `/interview?job=<id>`。
3. 保存失败时保留表单内容、显示现有错误通知且不跳转。
4. 面试页优先选中查询参数指定且真实存在的岗位；无效参数回退到列表首项。

## 验收标准

1. 两个保存动作同排且主次清晰，主按钮文案准确。
2. 主操作只创建一个岗位，成功后进入面试并选中刚保存的岗位。
3. 仅保存不跳转；失败时两个动作均不跳转。
4. 桌面与移动布局可读，键盘焦点、禁用态、状态反馈和 reduced motion 行为保留。
5. 定向测试、lint、typecheck、格式检查和生产构建通过。
