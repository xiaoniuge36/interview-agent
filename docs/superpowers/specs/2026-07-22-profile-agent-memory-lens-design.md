# 个人档案 Agent 记忆透镜设计

## 目标

将个人档案页从单纯的信息填写表单，收束为“这次保存会怎样影响下一轮训练”的 Agent 上游配置页。用户能够一眼看到 Agent 已采纳的证据、仍需补齐的训练信号，以及继续完善岗位目标的路径。

## 已确认约束

- 仅修改用户端档案页、其纯展示模型、局部样式和静态回归测试。
- 不修改档案 API、输入合同、保存逻辑、训练推荐算法、路由、认证、主题存储或依赖。
- 保留既有表单字段、校验、保存按钮、通知和 `/job` 跳转。
- 所有新旧局部颜色从既有主题 token 或 `color-mix()` 派生，支持 dawn、ocean、night 及 coral、blue、teal、amber 强调色。

## 设计方向：Agent 记忆透镜

页面对象是正在准备面试的候选人，单一任务是让他知道“填哪些信息，会让下一轮训练变得更贴近自己”。视觉签名是右侧 Agent 记忆透镜：不是通用进度栏，而是将档案信息拆为“已采纳”“下一步补齐”“训练如何变化”三段连续证据。

```text
档案信息 ──────────────── Agent 记忆透镜
候选人上下文               已采纳：技术栈 / 项目 / 级别
能力与项目证据             待补齐：目标岗位 / 项目证据
[保存并更新 Agent 记忆]    训练影响：推荐题、追问和复盘将如何变化
                            [继续完善目标岗位]
```

与“分步向导”相比，这一方案不伪造保存或分析进度；与纯样式翻新相比，它把用户真正需要的因果关系放到显眼位置。表单仍然服务于用户编辑，但 Agent 影响成为页面的解释主轴。

## 信息与交互

- 表单标题改为清晰的“训练画像输入”，说明只填写会影响推荐、追问和复盘的证据。
- 记忆透镜在已有完整度、优势证据与重点练习基础上，增加一组纯模型计算的“已采纳信号”和“下一步补齐”。这些均来自当前 `ProfilePayload`，不新增请求。
- 保存中的文案保持现有逻辑；成功或失败仍沿用 `aria-live` 文本与通知。透镜随 `WorkspaceGate` 的最新 profile 数据重新渲染。
- 桌面端保留编辑区与透镜并列；小于 1180px 时依次呈现表单、训练影响；小于 820px 时所有保存和后续行动占满宽度。

## 视觉与可访问性

- 色彩只使用 `--surface*`、`--outline*`、`--ink`、`--text-*`、`--primary*`、`--success*`、`--warning*`、`--agent-*` 和 `color-mix()`。
- 使用文本标签表达“已采纳”“待补齐”“训练影响”，不依赖颜色或图标传达状态。
- 保留全局键盘焦点；不引入必须运动的装饰，遵从全局减少动画设置。

## 验收标准

1. 档案页清晰解释当前资料对推荐题、追问和复盘的影响。
2. 空档案、部分档案和完整档案均有真实可执行的下一步，且不改变现有保存、验证和跳转。
3. `profile.css` 不保留硬编码十六进制颜色，并在三种主题与四种强调色下可读。
4. 静态测试覆盖记忆透镜的空、部分和完整档案语义；用户端定向测试、typecheck、lint、build 与差异检查通过。
