# 模型连接就绪度与设置中心设计

## 目标

让准备面试的用户在设置页一眼判断自己的默认模型能否用于 AI 评价、模拟面试和刷题教练，并在不能使用时获得准确、就近的下一步。页面的单一任务是把“添加连接、保存、测试、设为默认”从零散卡片动作组织成可信的训练前检查。

## 范围与约束

- 仅修改 `apps/user-portal` 的模型连接呈现、纯派生状态、静态测试和局部样式。
- 不修改模型连接 API、合同、加密、API Key 生命周期、测试请求、默认模型写入、调用统计接口或训练调用链。
- 就绪状态只能由 `ModelCredentialView.isDefault` 和 `status === 'verified'` 推导；最近测试时间和失败代码仅展示服务端已有值。
- 密钥始终只展示 `keyHint`；页面不记录或回显 API Key、提示词、回答正文或模型正文。

## 视觉方向：训练前检查章

设置页不再只是连接列表，而是一张训练前检查单。顶部的“就绪检查章”以明确文字说明默认模型状态：没有连接、需要测试/设默认、默认模型已就绪。它是唯一的视觉签名；其余连接卡、用量和编辑器保持安静、信息密度高且可核对。

基础主题值沿用现有 token：墨色 `#24242d`、表面 `#ffffff`、强调 `#df5c3b`、通过 `#12b981`。所有具体样式使用 CSS 变量或 `color-mix()`，以支持 dawn、ocean、night 与全部强调色。状态标签同时使用文字与布局，颜色只作为辅助。

```text
AI 模型 / 添加连接
─────────────────────────────────────
训练前检查：默认模型已就绪 / 仍需测试 / 尚未连接
连接卡：提供商、模型、默认标记、真实测试状态、仅必要动作
我的 AI 使用情况：真实调用、成功率、耗时、最近状态
```

## 交互与响应式

- 没有连接时，检查章与空状态都指向“添加模型连接”。
- 默认连接已验证时，只说明可以开始 AI 任务；不承诺模型质量、额度或可用时长。
- 默认连接未验证、已失败、已停用或不存在时，说明用户应在连接卡中测试或通过编辑器设为默认；不自动发起测试或改变默认项。
- 宽屏保持检查章、列表和用量的层次；760px 以下将操作区、卡片事实和用量指标折叠为可触达的单栏/双栏。

## 验收标准

1. 空连接、已验证默认连接、未验证/失败/停用默认连接、缺少默认连接都得到准确且可读的状态。
2. 连接卡仍保留保存、编辑、测试与删除行为；测试请求次数和默认模型写入行为不变。
3. 所有连接状态、检查章、空状态、编辑器和用量区域使用主题 token，设置 CSS 按 shell、模型检查/编辑、连接卡、用量四类职责拆分且每个文件不超过 300 行。
4. 纯状态、检查章和连接卡静态测试覆盖关键状态；用户端 typecheck、lint、测试和生产构建通过。
