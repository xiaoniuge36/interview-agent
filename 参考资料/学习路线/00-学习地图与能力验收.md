# 学习地图与能力验收

这套路线不是“看完八篇文章”，而是完成八次可验证的能力升级。每课都遵循同一个循环：理解原理、做出最小实现、制造失败、记录证据、用面试语言解释取舍。

## 学习目标

- 知道 AI Agent 工程师需要哪些能力，而不被具体框架牵着走。
- 为每一阶段定义可以检查的产出，而不是用学习时长代替掌握程度。
- 建立一条从原理、工程、评估到面试表达的统一路线。
- 确定毕业项目和最终验收标准。

## 学习闭环

### 1. Learn：形成可复述的心智模型

每个概念先回答四个问题：它解决什么问题、核心机制是什么、边界在哪里、失败时怎样定位。只会背定义，不算完成。

### 2. Build：做最小但完整的实现

实验必须包含输入、状态、输出和可观察记录。不要一开始就使用大型框架；先手写最小循环，再用框架比较它替你解决了什么。

### 3. Break：主动制造失败

至少覆盖一次超时、非法结构、无检索命中、重复请求或权限拒绝。Agent 工程能力更多体现在失败路径，而不是成功 Demo。

### 4. Verify：用指标和测试留下证据

保存固定输入、期望结果、运行日志、关键指标和失败样例。模型输出允许有随机性，但结构、权限、预算和业务事实必须确定。

### 5. Explain：转化成面试表达

用“问题—约束—方案—取舍—证据”讲清项目。不要只报框架名，要说明为什么没有选择另一种方案。

## 入学基线自测

给自己每项打 0–2 分：0 表示不会，1 表示能解释，2 表示能实现并验证。

| 能力        | 自测问题                                                     |
| ----------- | ------------------------------------------------------------ |
| Agent Loop  | 能否画出一次 Tool Calling 从模型到执行再回灌的完整状态变化？ |
| Context     | 能否说明历史消息、检索证据、工具描述如何竞争上下文预算？     |
| RAG         | 能否区分检索无命中、重排错误和生成不忠实？                   |
| Memory      | 能否区分事件、事实源、长期记忆和可重建投影？                 |
| Workflow    | 能否判断一个任务应使用确定性工作流还是开放 Agent？           |
| Evals       | 能否为 Agent 写出不依赖真实 Provider 的 CI 回归样例？        |
| Reliability | 能否设计超时、重试、幂等、熔断和降级？                       |
| Interview   | 能否用五分钟讲清一个项目并承受三层追问？                     |

低于 8 分按顺序学习；8–12 分可跳读基础课但必须完成实验；13 分以上从第 05 课开始，用评测反查知识缺口。

## 毕业项目

建议围绕一个真实场景完成“可评估的 Agent 系统”，例如面试训练 Agent、研究助手或企业知识问答。最低要求：

1. 至少一个类型化工具和一个检索能力。
2. 明确的状态机、停止条件和失败降级。
3. 可追溯来源，不把模型输出当业务事实直接写库。
4. 10 个以上 Golden Case，覆盖正常、边界和攻击输入。
5. 展示延迟、成功率、检索质量或成本中的至少两个指标。
6. 一份架构图、一段演示脚本和一组能写进简历的量化证据。

## 本课动手实验

建立自己的 `learning-evidence.md`，写下基线分数、目标岗位、毕业项目主题和八课产出链接。每完成一课，只追加证据，不修改历史分数；最后比较能力变化。

## 自测与面试表达

- 为什么“看过很多资料”不能证明会做 Agent？
- 为什么课程必须包含失败注入和评测？
- 你的毕业项目中，哪部分是确定性系统，哪部分允许模型不确定性？

推荐回答结构：先指出 Agent 是系统工程问题，再说明必须把非确定模型包在确定的权限、状态、验证和观测边界中，最后给出自己的实验或指标证据。
