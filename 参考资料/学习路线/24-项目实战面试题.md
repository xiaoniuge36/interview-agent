# 项目实战面试题：Interview Agent 与 Knowledge Hub

这一课不讲新框架，而是把已经做过的两个项目整理成面试时讲得清、经得起追问的证据。

两个项目分别是：

- **Interview Agent**：面试训练平台，重点是业务闭环、多租户、幂等状态机、混合检索和模型降级。
- **Knowledge Hub**：企业知识库，重点是文档管线、ES 混合检索、Agentic RAG、知识图谱、记忆和文档 ACL。

## 学习目标

- 能用一分钟讲清两个项目分别解决什么问题、技术栈和核心链路。
- 能画出架构图，并解释每个服务、存储和中间件的职责与边界。
- 能回答「为什么这样选」「失败怎么办」「怎么证明有效」三类追问。
- 能区分「已实现」和「规划中」，不把目标架构说成已有代码。

## 两个项目怎么讲

### Interview Agent：先讲业务闭环

回答顺序建议：

1. 用户建岗位意图，系统结合题库、掌握度和检索推荐题单。
2. 用户逐题作答，规则和模型共同评估，生成报告、错题本和掌握度。
3. Product API 是唯一事实源，Agent Runtime 只做受保护的工作流执行。
4. 模型调用统一走网关，支持多 Provider、预算、熔断和降级。
5. RAG 用关键词 + pgvector 混合检索，加权 RRF 融合，12 例 Golden 集做确定性评测。

被追问时优先展开：多租户怎么隔离、幂等怎么保证、模型失败怎么降级、检索效果怎么证明。

### Knowledge Hub：先讲检索质量

回答顺序建议：

1. 文档上传后统一解析成 Markdown，元数据进 PostgreSQL，正文进 MongoDB。
2. 发布后通过 RabbitMQ 跑三条管线：分块 Embedding 写 ES、文档级全文索引、LLM 抽实体关系写 Neo4j。
3. 问答先做意图路由，知识库走 ES 关键词 + kNN 混合检索，RRF 融合后 rerank。
4. 检索后做切题评估，不足则改写再查一次；图谱提供实体关系上下文。
5. 权限条件下沉到 ES filter 和 Neo4j where，短期记忆用 Redis，长期记忆用 Mem0。

被追问时优先展开：为什么用 ES 而不是 PGVector、RRF 和 rerank 的分工、切题评估为什么必要、图谱到底几跳、文档 ACL 怎么防止越权。

## 高频追问

### 为什么不用现成平台？

Dify 这类平台开箱即用，但自定义 Agentic 链路、知识图谱、文档级 ACL 和自研前端需要更深的控制权。自研的代价是运维和一致性复杂度更高，要能说清楚取舍。

### 怎么证明 RAG 有效？

不要只说「感觉变好了」。给评测集、指标和消融：

- 检索：Recall@5、MRR、nDCG@5、hit@5、precision@5。
- 生成：要点覆盖、忠实度、拒答质量。
- 对照：纯关键词 vs 混合检索，加 rerank 前后，改 chunk 前后。
- 失败样本：没召回、排错、答非所问、编造，分开归因。

### 多租户/权限怎么保证不串？

- 查询强制带租户条件，关键关联用复合外键。
- 检索前做 ACL 过滤，不是查完再 filter。
- ES 权限放 filter（不参与打分），Neo4j 权限放 WHERE，应用层二次校验。
- 用跨租户/跨团队用例做回归测试。

### 模型或依赖挂了怎么办？

- 模型失败：规则评估、模板报告、关键词检索。
- Reranker 失败：降级 RRF 顺序。
- Neo4j/Mem0 失败：跳过图谱/长期记忆，知识库问答继续。
- 关键依赖失败：快速暴露，不做假降级。

## 自测与面试表达

先用「本课题目与参考答案」速览自测：

1. 任选一道题，先口述 30 秒，再展开参考答案对照评分要点。
2. 重点练项目事实、取舍和失败路径，不要只背概念。
3. 每道题准备一个可核对的数字或配置，例如 chunk size、topK、RRF 参数、Golden 集规模。
