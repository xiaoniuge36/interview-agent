# 面试表达、手撕代码与毕业项目

面试不是把课程复述一遍，而是证明你能定义问题、做工程取舍、实现关键机制、用数据定位失败，并诚实说明系统边界。

## 学习目标

- 为概念题、系统设计题、项目深挖和故障题建立稳定回答结构。
- 选择与目标岗位匹配的手撕代码题，并能解释复杂度与测试。
- 完成一个可运行、可评测、可演示的 Agent 毕业项目。
- 把真实指标和个人贡献转化为简历与面试证据。

## 四类面试回答

### 概念题：定义—机制—边界—例子

回答“什么是 Agentic RAG”时，先定义模型会根据状态决定是否检索，再讲查询、工具和验证循环，随后说明单数据源低延迟场景不应使用，最后给出自己的消融结果。

### 取舍题：目标—约束—选项—证据

回答“单 Agent 还是 Multi-Agent”时，不比较框架热度。先说明角色权限、上下文隔离、并行性和质量门禁，再比较复杂度，最后用调用数、延迟或成功率证明选择。

### 系统设计题：边界—数据流—失败—观测—演进

先画 Product API、Runtime、Tool/Retrieval、Provider 和数据层，再沿一次请求解释状态；主动覆盖权限、幂等、超时、降级、指标和容量；最后说明从 MVP 到生产的演进触发条件。

### 项目深挖：问题—个人动作—取舍—结果—反思

每个数字都准备口径、基线、数据集和测量方式。没有线上流量就说“离线 50 个 Golden Case”，不要把实验数据包装成生产指标。

## 手撕代码能力树

### Agent 工程必做

1. Tool Calling 流式增量 JSON 组装：处理分片、多个 call、结束原因和非法片段。
2. 类型化 Tool Registry：Schema 校验、权限、超时、错误映射和幂等。
3. 有停止条件的 Agent Loop：最大步骤、总超时、重复动作和人工确认。
4. RRF 与 Recall@K/MRR：能写、能测，并解释 Reranker 的位置。
5. 带 Checkpoint 的状态机：中断恢复后不重复副作用。

### LLM 原理加分

根据目标岗位从 MHA、RoPE、RMSNorm、BPE、KV Cache、采样、InfoNCE、DPO 中选择两到三个。要求不是背 Notebook，而是：

- 先写输入输出形状与数学含义。
- 实现最小正确版本，再讨论向量化和数值稳定性。
- 用小数据构造 expected-first 断言和边界测试。
- 解释时间/空间复杂度以及它对推理或训练的影响。

Agent 应用开发岗优先 Tool Calling Parser、RRF、状态机和缓存；算法岗再强化 Attention、Tokenizer、对齐损失和消融实验。

## 毕业项目验收

选择一个范围可控的真实任务，例如面试训练 Agent、企业知识助手或研究助手。最低交付物：

| 交付物     | 验收证据                                  |
| ---------- | ----------------------------------------- |
| 需求与边界 | 用户、成功定义、非目标和风险清单          |
| 架构       | 状态机、信任边界、数据流和版本策略        |
| Agent 能力 | 至少一个 Tool、一个 Retrieval、一个恢复点 |
| 质量       | 20 个以上 Golden Case 和失败分类          |
| 安全       | 越权、Injection、重复副作用和费用攻击测试 |
| 生产       | P95、成功率、每成功任务成本和降级演练     |
| 演示       | 5 分钟脚本，包含正常路径与一次故障恢复    |
| 复盘       | 一个失败决策、一个消融实验和下一步计划    |

最终 benchmark 必须冻结数据集版本，分别报告确定性门禁、任务成功率、质量评分、P95 和成本。不要只展示最佳样例。

## 从项目到简历

使用“场景 + 个人动作 + 技术取舍 + 可复核结果”写项目，例如：

```text
为 30 类技术问题构建带引用的训练 Agent；设计混合检索、类型化工具和
可恢复状态机，在 60 条离线 Golden Case 上将任务成功率从基线 X 提升到 Y，
并通过模型路由把每成功任务成本从 A 降到 B。
```

只有在你保存了基线、评测脚本和运行结果时才能替换 X/Y/A/B。准备三种时长：30 秒项目定位、3 分钟完整闭环、10 分钟架构与 Bad Case 深挖。

## 模拟面试与复练

至少进行三轮：

1. 基础轮：Agent、Context、Tool、RAG、Memory 的概念与边界。
2. 系统轮：设计一个可恢复、可评测的生产 Agent。
3. 深挖轮：演示毕业项目并连续追问一次失败、一次取舍和一个指标。

每轮按准确性、结构、工程深度、证据和诚实边界各 0–4 分。低于 3 分的维度回到对应课程和题库复练；不要只重复背同一份答案。

## 本课动手实验

1. 完成一个 Agent 工程必做题和一个 LLM 原理加分题，各写测试。
2. 冻结毕业项目 benchmark，执行三次并报告均值与波动。
3. 录制 5 分钟演示，必须包含一次故障注入和恢复。
4. 写一页系统设计、一页 Bad Case 复盘和三条可验证简历表述。
5. 进入题库完成单选、多选和开放题，错题映射回 01–06 课。

## 毕业自测

- 能否不依赖框架名解释 Agent 的状态、动作、权限和停止条件？
- 能否用一次 Trace 定位 RAG、Tool 或模型的具体失败？
- 能否证明 Multi-Agent、缓存或模型路由确实带来收益？
- 能否现场写出关键算法并用测试证明边界正确？
- 能否明确说出项目尚未解决的问题和下一轮实验？

五项都能用产物回答，才算完成路线；否则根据证据回到对应专题复练。
