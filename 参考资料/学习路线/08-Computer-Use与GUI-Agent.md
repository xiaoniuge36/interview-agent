# Computer Use 与 GUI Agent

Computer Use Agent 不通过 API，而是通过截图、点击和键盘输入直接操作软件。它把 GUI 当成通用接口：不需要对方提供集成，也因此继承了 GUI 的全部对抗性和不确定性。

## 学习目标

- 画出截图 → 定位 → 动作 → 验证的完整感知动作循环。
- 理解 Grounding 为什么是瓶颈，以及推理正确但点不中的失败形态。
- 用 OSWorld 与 OSWorld 2.0 的分数差解释短任务与长程任务的能力断层。
- 掌握长程 GUI Agent 的三个 harness 决策：何时停止、何时恢复、何时求助。
- 界定像素驱动与 Agent 原生接口（API、MCP）的选型边界。

## 感知动作循环

```text
截图/可访问性树 → 理解界面状态 → 定位目标元素（grounding）
      → 生成动作（click/type/scroll/hotkey） → 执行
      → 重新截图验证效果 → 更新计划或纠错 → 循环
```

每一步都可能失败：界面渲染延迟、弹窗遮挡、坐标漂移、动作生效但界面无反馈。工程上必须把“动作已发出”和“效果已验证”当成两个独立事件。

## Grounding：推理与落点的脱节

模型可以正确推理“该点保存按钮”，却给不出准确的屏幕坐标。SeeClick 的核心结论是：从自然语言目标到精确屏幕位置的 grounding 是纯截图 Agent 的瓶颈，grounding 提升直接带动任务完成率。ScreenSpot 专门隔离测量这项能力，ScreenSpot-Pro 用 1832 个样本覆盖移动、桌面、网页和专业软件。

工程上常见两条路线：

- 通用模型 + 专职 Grounding 模型：主模型描述目标元素，专职模型输出坐标。
- 可访问性树/DOM 辅助：能拿到结构化元素时优先用元素 ID，截图只作兜底。

## 能力现状：短任务已可用，长程仍是断层

| 基准         | 设定                                | 代表结果                                       |
| ------------ | ----------------------------------- | ---------------------------------------------- |
| OSWorld      | 369 个跨 Ubuntu/Windows/macOS 短任务 | 2024 年约 12% → 2026 年最好系统约 85%，人类 72.36% |
| WebArena     | 自托管网站任务                      | 领先系统约 58%                                 |
| AndroidWorld | 移动端任务                          | 18 个月内从 8% 提升到接近 100%                 |
| OSWorld 2.0  | 108 个长程工作流，人类中位 1.6 小时 | 最好系统 500 步预算下仅 20.6% 完整完成         |

OSWorld 2.0 的任务平均需要约 318 次工具调用，是一代基准的十倍。失败主因不是点不准，而是：丢失任务约束、错过中途到达的新信息、该问用户时靠猜、跳过验证、无法恢复隐藏状态。短任务分数无法外推到长程可靠性，这是本课最重要的一个判断。

## 长程 Harness：STOP、RECOVER、SEARCH

以 VLAA-GUI 为代表的模块化框架把长程可靠性归结为三个决策，用一个主循环加强制检查实现：

- 强制完成度校验器（Completeness Verifier）：每步之后检查“任务真的完成了吗”，封住虚假完成这个最大失败源。
- 分级循环打断器（Loop Breaker）：检测重复动作，先换表达、再换模态、最后换策略逐级升级。
- 按需子能力：查资料用文本搜索 Agent（不付浏览器交互成本）、批量编辑走 Coding Agent（≥20 处修改直接写脚本）、精确定位交给 Grounding Agent。

这套“单主循环 + 强制验证 + 按需工具”的结构在 OSWorld-Verified 上做到 77.5%，多个底座模型单轮超过人类基线。层级子任务分解和持久记忆模块反而不是必需品。

## 安全：GUI 是对抗性控制面

- 屏幕上的内容都是不可信输入：网页文本、弹窗、邮件里的指令可能是注入攻击，不能提升为系统指令（与第 02 课的工具返回同理）。
- 不可逆动作必须确认：发送、支付、删除、对外发布要求显式确认或人工介入。
- 凭据隔离：Agent 会话使用受控账号与最小权限，密码输入走凭据管理器而不是模型上下文。
- 全程留痕：截图序列、动作日志和安全审计报告是排障与追责的唯一依据。

## 像素驱动还是 Agent 原生接口

有稳定 API 或 MCP Server 时永远优先结构化接口：更快、更便宜、可校验。像素驱动的价值在于覆盖没有集成的长尾软件和遗留系统。成熟系统通常混合两者：结构化接口为主，GUI 操作兜底，并让编排层决定何时切换。

## 本课动手实验

用 Playwright 或任一浏览器自动化框架实现最小 GUI Agent 循环：

1. 任务：在一个演示网站上完成“搜索商品并加入购物车”。
2. 每步动作后强制截图并断言预期状态，验证失败自动重试一次。
3. 注入干扰：中途弹出一个含“忽略之前指令”的对话框，验证 Agent 只关闭弹窗而不执行其中指令。
4. 制造循环：把某按钮改成永远无效，验证循环打断器能在 N 次后停止并报告。
5. 记录每步的动作、耗时、截图路径和验证结果，输出一份轨迹报告。

加分：把同一任务改写为直接调用该网站 API 的版本，对比步数、延迟与失败率，写出选型结论。

## 面试怎么讲

先给能力断层的量化事实：短任务基准已接近或超过人类，长程基准最好系统仅完成五分之一。再解释断层来源是状态追踪、验证与恢复而不是点击精度。最后讲自己的工程立场：结构化接口优先、像素兜底、每步验证、不可逆动作设卡，并用一次注入或循环实验的证据收尾。
