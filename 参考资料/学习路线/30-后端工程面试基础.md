# 后端工程面试基础：网络、数据库与并发

后端面试的基础知识部分（俗称八股）考察范围稳定：网络、数据库、操作系统与并发。高分答案和及格答案的差别不在知识点本身，而在**答题结构**：先给结论，再讲机制，最后落到工程实践中的取舍。本课给出高频考点地图和可复用的答题框架。

## 学习目标

- 掌握三大高频领域的考点分布，把复习时间花在出现率最高的 20% 上。
- 会用「结论 → 机制 → 工程实践」三段式回答概念题。
- 每个核心概念都能再向下答一层（面试官追问层）。
- 能把八股答案与自己的项目经历勾连，从背诵转向证明。

## 网络：从一次 HTTP 请求说起

最高频的开放题是"从输入 URL 到页面展示发生了什么"，它是网络知识的索引题。你需要能在每一站停下来深讲：

- **DNS**：递归与迭代查询、缓存层级（浏览器/系统/运营商）、DNS 劫持的应对。
- **TCP 建连**：三次握手的目的是同步序列号并确认双方收发能力，防止历史连接误建。追问层：为什么不是两次（无法防止旧 SYN 造成的错误建连）、TIME_WAIT 为什么要等 2MSL。
- **TLS**：非对称交换密钥、对称加密数据；证书链验证解决"公钥是谁的"问题。
- **HTTP 语义**：301/302 的缓存与权重差异、强缓存与协商缓存（Cache-Control / ETag）、HTTP/2 多路复用解决的队头阻塞在 TCP 层依然存在（这正是 QUIC 的动机）。

答题框架示例——"301 和 302 有什么区别"：

> 结论：301 永久、302 临时。机制：浏览器会长期缓存 301，搜索引擎会把权重转移到新地址；302 每次仍请求原地址。工程实践：域名迁移用 301，活动页临时跳转用 302——我们踩过把 301 用在临时跳转上、导致老地址被缓存改不回来的坑。

## 数据库：索引与事务是必考区

**索引**的追问链通常是：B+ 树为什么适合磁盘（矮胖、范围扫描友好、叶子节点链表）→ 什么情况索引失效（对索引列使用函数、隐式类型转换、前导通配符 LIKE、不满足最左前缀）→ 怎么定位慢查询（EXPLAIN 看 type 和 rows，关注 filesort 与临时表）。

**事务**的追问链：四个隔离级别各解决什么问题 → MySQL 默认可重复读怎么实现（MVCC + 间隙锁）→ 什么场景仍会出现幻读 → 业务上什么时候需要串行化或乐观锁。

高分技巧：把答案落到自己的项目。"我们订单表的深分页问题最后用游标分页解决"比十条背诵更有说服力。

## 操作系统与并发：区分概念，落到场景

- **进程 vs 线程**：资源分配单位 vs 调度单位；同进程线程共享地址空间所以切换轻量，但一个线程崩溃可能连累整个进程。追问层：协程为什么更轻（用户态调度、栈更小）。
- **并发控制**：悲观锁 vs 乐观锁的选择依据是冲突概率——高冲突用悲观（避免大量重试），低冲突用乐观（避免锁开销）。追问层：CAS 的 ABA 问题、数据库乐观锁的版本号实现。
- **死锁**：四个必要条件（互斥、持有并等待、不可剥夺、循环等待），工程上最常用的预防是**固定加锁顺序**。

## 答题的三条纪律

1. **先结论后展开**：概念题第一句话就是答案，不要从背景讲起。
2. **主动给出边界**："这个结论在 X 场景下不成立"——展示你理解适用条件，而不是背了一段话。
3. **不会就说不会，然后给推理**："这个点我没深入过，但基于 X 原理我推测……"比硬编可信得多。

## 面试前的准备清单

1. 用"从输入 URL 到页面展示"做一次自我串讲，每一站能停下来深讲两分钟。
2. 对索引失效和事务隔离各准备一个自己项目里的真实案例。
3. 把最近项目里的一次性能优化整理成「现象 → 定位 → 方案取舍 → 数字结果」四段。

## 自测

完成以下检查后，进入题库验证本课概念：

- TCP 为什么需要三次握手而不是两次？TIME_WAIT 的作用是什么？
- 列举至少三种索引失效的写法，并说明各自的原因。
- 悲观锁与乐观锁的选择依据是什么？你的项目里用的是哪种，为什么？
